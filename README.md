# ГОСТ-RAG

Открытый ассистент по российским стандартам и машиностроительной документации.
Отвечает на вопросы инженеров-конструкторов и технологов по-русски и **всегда
показывает, из какого документа, пункта и страницы взят ответ**.

```
Вопрос:  Какой радиус гибки у листовой стали толщиной 3 мм по ГОСТ?
Ответ:   Минимальный радиус гибки — 2S, то есть 6 мм [S1]. Для сталей
         повышенной прочности — 2,5S [S2].
Источники:
  [S1] ГОСТ 17040-71 (действующий), п. 3.2, стр. 7
  [S2] ГОСТ 17040-71 (действующий), табл. 4, стр. 9
```

Проект намеренно построен как **честный baseline**: фиксированные чанки,
гибридный поиск, RRF, кросс-энкодер. Никаких multi-query и HyDE — они появятся
позже и должны будут доказать своё превосходство числами из `eval/`.

## Как это устроено

```
PDF/DOCX ──► текст + таблицы ──► OCR для сканов ──► чанки 800 ток. / 10 % ──► BGE-M3
                                                                                │
                                                                     ┌──────────┴──────────┐
                                                                     │  Qdrant: dense +    │
                                                                     │  sparse векторы     │
                                                                     └──────────┬──────────┘
                                                                                │
запрос ──► фильтр по обозначению ──► dense + sparse префетч ──► RRF ──► реранкер ──► LLM
                                                                                     │
                                                                    проверка цитат ──┘
```

| Слой | Технология | Почему |
|---|---|---|
| Оркестрация | LangGraph | Явные узлы: multi-query добавляется вставкой узла, а не переписыванием |
| Генерация | DeepSeek V4 Flash (по умолчанию) | OpenAI-совместимый API; провайдер меняется в `.env` |
| Эмбеддинги | BAAI/bge-m3 | Плотный и разреженный вектор за один проход, сильный русский |
| Реранкер | BAAI/bge-reranker-v2-m3 | Кросс-энкодер, решающий на технических формулировках |
| Индекс | Qdrant | Именованные dense+sparse векторы, RRF на стороне базы |
| Интерфейс | FastAPI + SSE | Один процесс, без сборки фронтенда |

### Ключевые решения

**Таблицы не режутся.** Ответы вида «радиус гибки для толщины 3 мм» живут в
таблицах, поэтому таблица — неделимый блок; если она не влезает в окно, делится
по строкам с повтором заголовка. Области таблиц вырезаются из текстового слоя,
иначе ячейки попадают в индекс дважды — связной таблицей и россыпью чисел.

**Статус стандарта виден всегда.** «Отменён» и «заменён» показываются рядом с
каждой цитатой: ответ по недействующему стандарту хуже, чем отсутствие ответа.
Статус берётся из реестра, а не из текста — стандарт не сообщает о своей отмене.

**Отказ вместо выдумки.** Если после переранжирования не осталось релевантных
фрагментов, LLM не вызывается вовсе. Модели, которой нечего цитировать,
свойственно отвечать по памяти, а правдоподобно выдуманный номер пункта —
худший из возможных исходов.

**Цитаты проверяются.** Ссылка `[S7]` при шести фрагментах вырезается из ответа
до того, как он дойдёт до пользователя.

## Установка

Нужны [uv](https://docs.astral.sh/uv/) и Python 3.12 (на 3.13 колёса `torch` и
`FlagEmbedding` под Windows пока ненадёжны — `uv` подтянет 3.12 сам).

```bash
git clone https://github.com/gkami1/gost-rag
cd gost-rag
uv sync --extra dev
cp .env.example .env        # Windows: copy .env.example .env
```

Впишите в `.env` ключ провайдера:

```ini
LLM_PROVIDER=deepseek
LLM_API_KEY=sk-...
```

Поддерживаются `deepseek`, `qwen`, `yandex` и `custom` — любой OpenAI-совместимый
эндпоинт. Смена провайдера не требует правок кода.

### OCR (для сканов)

Много ГОСТов существует только в виде сканов. Без Tesseract они будут
пропущены — индексация не упадёт, но такие документы в корпус не попадут.

* **Windows:** [установщик UB Mannheim](https://github.com/UB-Mannheim/tesseract/wiki),
  обязательно отметьте языковой пакет **Russian**. Если бинарь не в `PATH`,
  укажите путь в `.env`: `TESSERACT_CMD=C:\Program Files\Tesseract-OCR\tesseract.exe`
* **Linux:** `sudo apt install tesseract-ocr tesseract-ocr-rus`
* **macOS:** `brew install tesseract tesseract-lang`

Проверка: `tesseract --list-langs` должен показать `rus`.

## Использование

```bash
# 1. Положите PDF/DOCX в data/raw/ и опишите их в data/registry/documents.csv
# 2. Проиндексируйте
uv run python scripts/ingest.py data/raw

# 3. Проверьте поиск без LLM
uv run python -m gost_rag.retrieval.cli "какой радиус гибки листовой стали 3 мм"

# 4. Запустите интерфейс
uv run python scripts/serve.py     # http://127.0.0.1:8000
```

Первый запуск скачивает ~2,5 ГБ весов (BGE-M3 и реранкер). На CPU индексация
идёт заметно медленнее, чем на GPU; `EMBED_BATCH_SIZE` регулирует расход памяти.

Полезные флаги индексации:

| Флаг | Зачем |
|---|---|
| `--recreate` | Пересоздать коллекцию с нуля |
| `--no-resume` | Не пропускать уже разобранные файлы |
| `--approx-tokens` | Не грузить токенайзер BGE-M3 (быстрая проверка конвейера) |

Повторный запуск безопасен: ID чанка выводится из хэша текста, поэтому
неизменившийся документ переиндексируется вхолостую.

## Оценка

```bash
uv run python eval/run_eval.py --k 10
```

Считает recall@k и MRR на трёх срезах — только плотный поиск, после RRF и после
реранкера, — чтобы видеть вклад каждой стадии по отдельности, а также долю
отказов на вопросах, которых заведомо нет в корпусе.

`eval/questions.yaml` — **шаблон**. Замените обозначения на те, что реально есть
в вашем корпусе, иначе нулевые метрики будут означать пустой эталон, а не плохой
поиск (скрипт об этом предупредит).

## Корпус

**Тексты стандартов в репозиторий не входят.** `data/raw/` в `.gitignore`;
репозиторий содержит код индексации и реестр `data/registry/documents.csv`
с обозначениями, статусами и ссылками на источники — по нему корпус
восстанавливается локально. Публичное распространение текстов стандартов —
юридический риск, перечень документов — нет.

Ответы ассистента не заменяют официальный текст стандарта. Проверяйте
актуальность редакции перед применением.

## Разработка

```bash
uv run pytest          # тесты (без сети и без загрузки моделей)
uv run ruff check .
uv run ruff format .
```

Тесты не тянут веса: чанкинг проверяется на подставном токенайзере, поиск — на
встроенном Qdrant с синтетическими векторами, граф — с фиктивными LLM и
реранкером. Поэтому полный прогон занимает секунды.

## Что дальше

Baseline осознанно оставляет место для улучшений — каждое должно проверяться
через `eval/`:

- переписывание уточняющих вопросов с учётом истории диалога (сейчас поиск идёт
  по последнему вопросу как есть);
- multi-query и HyDE;
- чанкинг по структуре документа вместо фиксированного окна;
- разбор чертежей и схем;
- автоматическая проверка статуса стандартов по внешнему реестру.
