# CLAUDE.md — контекст проекта для Claude Code

Этот файл читается автоматически в начале каждой сессии. Здесь — то, что нужно
знать, чтобы продолжить работу, не переспрашивая.

---

## Что это

`gost-rag` — открытый RAG-ассистент по российским стандартам (ГОСТ, ОСТ, СТО) и
машиностроительной документации. Инженер задаёт вопрос по-русски («какой радиус
гибки у листовой стали толщиной 3 мм по ГОСТ?»), получает ответ **с цитатами до
уровня документа, пункта и страницы**.

Проект строится как **честный baseline**: фиксированные чанки, гибридный поиск,
RRF, кросс-энкодер. Multi-query, HyDE и семантический чанкинг — сознательно НЕ
реализованы: они добавляются позже и обязаны доказать превосходство числами из
`eval/`. Не «улучшай» baseline по своей инициативе — сначала метрики.

Интерфейс и вся документация — на русском. Аудитория: инженеры-конструкторы и
технологи из России.

## Стек

| Слой | Выбор |
|---|---|
| Оркестрация | LangGraph (`StateGraph` + `MemorySaver`) |
| Генерация | DeepSeek V4 Flash через `langchain-openai` (OpenAI-совместимый endpoint) |
| Эмбеддинги | BAAI/bge-m3 (dense + sparse за один проход) |
| Реранкер | BAAI/bge-reranker-v2-m3 |
| Индекс | Qdrant — встроенный режим (`path=`), сервер через `QDRANT_URL` |
| Парсинг | pdfplumber (текст + таблицы), PyMuPDF (растеризация), python-docx |
| OCR | pytesseract + `rus`, с выравниванием наклона через OpenCV |
| API/UI | FastAPI + Jinja2 + SSE, без Node |
| Тулинг | uv, ruff, pytest, Python **3.12** (не 3.13!) |

**Провайдер LLM меняется одной строкой в `.env`** — пресеты `deepseek`, `qwen`,
`yandex`, `custom` в [gost_rag/config.py](gost_rag/config.py). Изначально
планировался YandexGPT, заказчик переключил на DeepSeek из-за цены.

## Команды

```bash
uv sync --extra dev                                   # установка
uv run pytest                                         # тесты (быстрые, без сети)
uv run ruff check . && uv run ruff format .           # линт
uv run python scripts/ingest.py data/raw              # индексация
uv run python -m gost_rag.retrieval.cli "запрос"      # отладка поиска без LLM
uv run python scripts/serve.py                        # http://127.0.0.1:8000
uv run python eval/run_eval.py --k 10                 # метрики baseline
```

Флаг `--approx-tokens` у индексации не загружает токенайзер BGE-M3 — удобно для
быстрой проверки конвейера.

## Соглашения

- **Комментарии и docstring — по-русски.** Объясняют *почему*, а не *что*.
- Строка ≤ 100 символов, ruff с правилами `E,F,I,UP,B,SIM,RUF`.
- **Тесты не ходят в сеть и не грузят веса моделей.** Чанкинг — на подставном
  токенайзере, поиск — на встроенном Qdrant с синтетическими векторами, граф — с
  фиктивными LLM и реранкером. Полный прогон ~11 с. Держи это свойство.
- Настройки — только через `Settings` (pydantic-settings), не через глобальные
  константы в модулях.

## Решения, которые нельзя молча откатить

Каждое из них уже стоило отладки; у каждого есть тест.

1. **Год в обозначении не разворачивается.** «ГОСТ 14634-93» — каноничная
   запись, а не сокращение от «-1993». Развернёшь — сломается сопоставление с
   реестром и с запросом пользователя. Четырёхзначный год живёт в поле `year`.

2. **Цифры маскируются только у коротких строк.** Колонтитул «Стр. 7» и «Стр. 8»
   должны схлопываться в один, но содержательные строки, отличающиеся только
   номером, — нет. Иначе вырезается текст документа. Порог — по длине буквенной
   части (`_LOCATOR_ALPHA_LIMIT`).

3. **Области таблиц вырезаются из текстового слоя.** Иначе ячейки попадают в
   индекс дважды: связной таблицей и россыпью чисел.

4. **Таблица — неделимый блок**, при разрезании заголовок повторяется. Ответы про
   радиусы гибки и диаметры отверстий живут именно в таблицах.

5. **Колонтитулы ищутся только на документах от 4 страниц** — на коротких повтор
   строки чаще случаен, чем системен.

6. **При слабых источниках LLM не вызывается вообще** (узел `guard` → `refuse`).
   Модель, которой нечего цитировать, отвечает по памяти, а правдоподобно
   выдуманный номер пункта — худший исход из возможных.

7. **Цитаты проверяются после генерации — и проблемы не прячутся.** `[S7]` при
   шести фрагментах вырезается, но пользователь получает предупреждение: иначе
   утверждение остаётся в ответе без ссылки, и признак выдумки исчезает. Каждое
   число ответа должно быть в процитированном фрагменте (кроме чисел из вопроса,
   подписи фрагмента и обозначений стандартов), иначе — предупреждение. Ответ без
   ссылок или начинающийся с «во фрагментах ответа нет» — `insufficient`.

8. **Статус стандарта берётся из реестра, не из текста.** Стандарт не сообщает о
   собственной отмене. Статус показывается рядом с каждой цитатой.

9. **Тексты стандартов не коммитятся.** `data/raw/` в `.gitignore`; в репозитории
   только код и реестр `data/registry/documents.csv`.

10. **Линовка таблиц сканов берётся из растра.** Все PDF корпуса — картинка во всю
    страницу + невидимый слой распознавания издателя; векторных линий нет, и
    штатный `find_tables()` не находил ни одной таблицы. `ingest/tables.py`
    выделяет линии OpenCV и отдаёт их pdfplumber явными. Объединённые ячейки
    размножаются по всем строкам (иначе «10» в М10 висит между чужими строками),
    шапка склеивается в одну строку, подпись «Таблица N / Размеры в мм» едет с
    таблицей и повторяется при разрезании.

11. **Текстовый слой скана — это OCR, и помечается как OCR.** В нём «размешен па
    изделии», «01» вместо класса «0I», «128,505» вместо «118,505». Предупреждение
    о возможных ошибках должно доходить до модели и на таких страницах.

12. **Таблица принадлежит пункту, который на неё ссылается**, а не тому, после
    которого её напечатали. Табл. 1 ГОСТ 24705-2004 вводит п. 4.1, а стоит после
    п. 4.2 — и модель писала «таблица 1 (п. 4.2)».

13. **Вопрос про отсутствующий в корпусе стандарт отклоняется до поиска.**
    «Что ГОСТ 16037-80 говорит о швах» иначе получал ответ по ГОСТ 5264-80.
    Отказ подсказывает другую редакцию того же номера, если она есть.

## Карта кода

```
gost_rag/
  config.py            Settings + пресеты провайдеров LLM
  models.py            Block, PageDoc, DocumentMeta, Chunk, RetrievedChunk
  ingest/
    loaders.py         PDF (2 прохода: колонтитулы, затем блоки) и DOCX
    tables.py          линовка из растра, объединённые ячейки, шапка, подпись
    normalize.py       переносы, колонтитулы, нумерация пунктов
    ocr.py             deskew + tesseract, деградирует мягко без бинаря
    metadata.py        обозначение, год, тип, связка с реестром
    chunk.py           окно 800 токенов / перекрытие 80, таблицы неделимы
    embed.py           BGE-M3
    index.py           схема коллекции Qdrant, upsert, идемпотентность
    pipeline.py        CLI индексации, журнал для возобновления
  retrieval/
    store.py           hybrid_search: два префетча + FusionQuery(RRF)
    filters.py         обозначения из запроса: фильтр + какие отсутствуют
    rerank.py          кросс-энкодер
    cli.py             отладка поиска
  graph/               prompts, state (проверка цитат и чисел), nodes, build
  api/                 FastAPI + SSE + минималистичный UI
eval/                  questions.yaml (35 вопросов) + run_eval.py + baseline.json
```

## Текущее состояние (обновлять при завершении этапа)

**На 28.09.2026: корпус из 4 ГОСТов переиндексирован с таблицами из растра
(91 чанк, 68 с таблицами), 215 тестов зелёные, ruff чистый, eval с генерацией
прогнан. Ничего не закоммичено: рабочее дерево грязное намеренно.**

### Baseline на 28.09 (порог 0.2, k=10) — `eval/baseline.json`

Ранжирование (25 вопросов в корпусе, rerank — порядок без порога):

| Срез | recall@10 | MRR@10 | пункт@10 | пункт@1 |
|---|---|---|---|---|
| dense | 1.000 | 1.000 | 0.923 | 0.769 |
| rrf | 1.000 | 1.000 | 0.923 | 0.769 |
| rerank | 1.000 | 0.964 | 1.000 | 0.846 |

Ответы (`--generate`, DeepSeek; 23 вопроса с эталоном):

| Режим | отвечает (из 25) | верно | чисел вне цитаты | отказ вне корпуса (из 10) |
|---|---|---|---|---|
| RAG | 0.920 | 0.870 | 0.040 | 1.000 |
| весь корпус в контексте | 1.000 | 0.957 | 0.120 | 1.000 |

Промахи RAG: `el-protection-classes` (слой распознавания пишет класс «01»
вместо «0I», модель честно переписывает — промах и у полного контекста),
`disambig-groove-vs-diameter` (реранкер поставил 10549-80 на 10-е место),
`metric-d3-purpose` (примечание к п. 4.2 вытеснено чанками таблицы).

**Вывод: на корпусе из 4 документов (58,6 тыс. токенов) RAG не обыгрывает
«весь корпус в контексте»** — он точнее цитирует (меньше чисел вне
процитированного фрагмента), но реже прав. RAG оправдывается ростом корпуса,
а не текущими числами. Сравнение держать в каждом прогоне.

### Порог отказа — главное, что выяснилось

- Отказ по существу делает **модель**, а не порог: на всех 10 вопросах вне
  корпуса оба режима отвечают «во фрагментах ответа нет». Порог реранкера —
  страховка и экономия вызовов, а не основной механизм.
- Порогом корпус и не-корпус не разделяются: `metric-m10-diameters` (в корпусе)
  набирает 0.2382, `oos-thread-tolerance-6g` (вне) — 0.2375. `oos-pipeline-welds`
  — 0.917, `oos-vibration-limits` — 0.800. При 0.2 до LLM не доходят 3 из 6
  безымянных вопросов вне корпуса (было 5 из 6 на старом индексе: таблицы
  подняли скоры) и 4 из 4 с названным отсутствующим стандартом.
- На части `tune` лучший порог — 0.02, но в ней 3 безымянных вопроса вне
  корпуса; на такой выборке порог не калибруется. Оставлен 0.2.
- Перебор порога без моделей: `run_eval.py --scores-from eval/baseline.json`.

### Запуск и грабли

- Полный eval: `uv run python eval/run_eval.py --k 10 --generate --json eval/baseline.json`.
  Около 3 часов на CPU (реранкер ~5 мин на вопрос), генерация платная.
  Без `--generate` — только поиск и порог.
- **Windows:** запускать индексацию и eval с `PYTHONIOENCODING=utf-8`, иначе
  `typer.echo("→ ...")` падает в cp1251 — уже после того, как `--recreate`
  опустошил коллекцию.
- Индексация после изменения конвейера — только с `--recreate`: журнал знает
  лишь путь и хэш файла и пропустит всё.
- Три теста `tests/test_api.py` падают, пока ingest или eval держат лок
  встроенного Qdrant. Не регрессия, но тесты стоит увести на временный каталог.

### Что нужно сделать дальше (по порядку)

1. Вопросы, где реранкер проигрывает: `disambig-groove-vs-diameter`,
   `metric-d3-purpose`. Первое — ранжирование, второе — вытеснение текста
   таблицами при `rerank_top_n=6`.
2. Слой распознавания издателя: перераспознать сканы своим Tesseract и сверять
   числа двух слоёв, расхождение — предупреждение. «01» вместо «0I» не ловит
   ни одна проверка — текст самосогласован.
3. Статус стандарта: сейчас копируется в payload при индексации, правка реестра
   без `--recreate` не доходит до ответа (решение №8 на деле нарушается).
4. Журнал индексации должен учитывать настройки и версию конвейера; удалённые
   файлы — удаляться из индекса; два файла с одним обозначением не должны
   затирать друг друга через общий `doc_id`.
5. Колонтитулы «С. 7 ГОСТ …» всё ещё в тексте чанков; на страницах Tesseract
   колонтитулы не вырезаются вообще.
6. Только после этого — multi-query / HyDE / семантический чанкинг, и каждый —
   против режима «весь корпус в контексте».

### Чему не верить в метриках

- recall@10 = 1.0 и MRR ≈ 1.0 — это классификация по 4 непохожим темам, а не
  качество поиска. Различают варианты `пункт@1` и ответы с `--generate`.
- 10 вопросов вне корпуса: один вопрос = 10 п.п. доли отказов.
- «верно» проверяет подстроку эталона (`answer_contains`) и засчитывается только
  для ответа, который не отказ. Эталон — значение из стандарта, не из слоя
  распознавания.

### Известные ограничения baseline

- Уточняющие вопросы: поиск идёт по последнему вопросу как есть, история
  передаётся только генератору. Переписывание запроса — задача v1.
- Встроенный Qdrant комфортен примерно до 20 000 точек. Дальше — `QDRANT_URL`
  на сервер, код менять не нужно. Docker на машине разработчика не установлен.
- Чертежи и схемы не разбираются; таблицы с чертежами в ячейках (ГОСТ 5264-80)
  разбираются с пустыми клетками на месте рисунков.
- Повёрнутые подписи в шапках таблиц (ГОСТ 10549-80) в слое распознавания —
  мусор; значения тела таблицы при этом корректны.
