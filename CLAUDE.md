## Что это

`gost-rag` — открытый RAG-ассистент по российским стандартам (ГОСТ, ОСТ, СТО) и
машиностроительной документации. Инженер задаёт вопрос по-русски («какой радиус
гибки у листовой стали толщиной 3 мм по ГОСТ?»), получает ответ **с цитатами до
уровня документа, пункта и страницы**.

Проект строится как **честный baseline**: фиксированные чанки, гибридный поиск,
RRF, кросс-энкодер. Multi-query, HyDE и семантический чанкинг — сознательно НЕ
реализованы: они добавляются позже и обязаны доказать превосходство числами из
`eval/`. Не «улучшай» baseline по своей инициативе — сначала метрики.

Интерфейс и вся документация — на русском. Аудитория: инженеры-конструкторы и
технологи из России.

## Стек

| Слой | Выбор |
|---|---|
| Оркестрация | LangGraph (`StateGraph` + `MemorySaver`) |
| Генерация | DeepSeek V4 Flash через `langchain-openai` (OpenAI-совместимый endpoint) |
| Эмбеддинги | BAAI/bge-m3 (dense + sparse за один проход) |
| Реранкер | BAAI/bge-reranker-v2-m3 |
| Индекс | Qdrant — встроенный режим (`path=`), сервер через `QDRANT_URL` |
| Парсинг | pdfplumber (текст + таблицы), PyMuPDF (растеризация), python-docx |
| OCR | pytesseract + `rus`, с деskew через OpenCV |
| API/UI | FastAPI + Jinja2 + SSE, без Node |
| Тулинг | uv, ruff, pytest, Python **3.12** (не 3.13!) |

**Провайдер LLM меняется одной строкой в `.env`** — пресеты `deepseek`, `qwen`,
`yandex`, `custom` в [gost_rag/config.py](gost_rag/config.py). Изначально
планировался YandexGPT, заказчик переключил на DeepSeek из-за цены.

## Команды

```bash
uv sync --extra dev                                   # установка
uv run pytest                                         # тесты (быстрые, без сети)
uv run ruff check . && uv run ruff format .           # линт
uv run python scripts/ingest.py data/raw              # индексация
uv run python -m gost_rag.retrieval.cli "запрос"      # отладка поиска без LLM
uv run python scripts/serve.py                        # http://127.0.0.1:8000
uv run python eval/run_eval.py --k 10                 # метрики baseline
```

Флаг `--approx-tokens` у индексации не загружает токенайзер BGE-M3 — удобно для
быстрой проверки конвейера.

## Соглашения

- **Комментарии и docstring — по-русски.** Объясняют *почему*, а не *что*.
- Строка ≤ 100 символов, ruff с правилами `E,F,I,UP,B,SIM,RUF`.
- **Тесты не ходят в сеть и не грузят веса моделей.** Чанкинг — на подставном
  токенайзере, поиск — на встроенном Qdrant с синтетическими векторами, граф — с
  фиктивными LLM и реранкером. Полный прогон ~11 с. Держи это свойство.
- Настройки — только через `Settings` (pydantic-settings), не через глобальные
  константы в модулях.

## Решения, которые нельзя молча откатить

Каждое из них уже стоило отладки; у каждого есть тест.

1. **Год в обозначении не разворачивается.** «ГОСТ 14634-93» — каноничная
   запись, а не сокращение от «-1993». Развернёшь — сломается сопоставление с
   реестром и с запросом пользователя. Четырёхзначный год живёт в поле `year`.

2. **Цифры маскируются только у коротких строк.** Колонтитул «Стр. 7» и «Стр. 8»
   должны схлопываться в один, но содержательные строки, отличающиеся только
   номером, — нет. Иначе вырезается текст документа. Порог — по длине буквенной
   части (`_LOCATOR_ALPHA_LIMIT`).

3. **Области таблиц вырезаются из текстового слоя.** Иначе ячейки попадают в
   индекс дважды: связной таблицей и россыпью чисел.

4. **Таблица — неделимый блок**, при разрезании заголовок повторяется. Ответы про
   радиусы гибки и диаметры отверстий живут именно в таблицах.

5. **Колонтитулы ищутся только на документах от 4 страниц** — на коротких повтор
   строки чаще случаен, чем системен.

6. **При слабых источниках LLM не вызывается вообще** (узел `guard` → `refuse`).
   Модель, которой нечего цитировать, отвечает по памяти, а правдоподобно
   выдуманный номер пункта — худший исход из возможных.

7. **Цитаты проверяются после генерации.** `[S7]` при шести фрагментах вырезается
   из ответа до того, как он дойдёт до пользователя.

8. **Статус стандарта берётся из реестра, не из текста.** Стандарт не сообщает о
   собственной отмене. Статус показывается рядом с каждой цитатой.

9. **Тексты стандартов не коммитятся.** `data/raw/` в `.gitignore`; в репозитории
   только код и реестр `data/registry/documents.csv`.

## Карта кода

```
gost_rag/
  config.py            Settings + пресеты провайдеров LLM
  models.py            Block, PageDoc, DocumentMeta, Chunk, RetrievedChunk
  ingest/
    loaders.py         PDF (2 прохода: колонтитулы, затем блоки) и DOCX
    normalize.py       переносы, колонтитулы, нумерация пунктов
    ocr.py             deskew + tesseract, деградирует мягко без бинаря
    metadata.py        обозначение, год, тип, связка с реестром
    chunk.py           окно 800 токенов / перекрытие 80, таблицы неделимы
    embed.py           BGE-M3
    index.py           схема коллекции Qdrant, upsert, идемпотентность
    pipeline.py        CLI индексации, журнал для возобновления
  retrieval/
    store.py           hybrid_search: два префетча + FusionQuery(RRF)
    filters.py         обозначение из запроса -> фильтр (если есть в корпусе)
    rerank.py          кросс-энкодер
    cli.py             отладка поиска
  graph/               prompts, state (проверка цитат), nodes, build
  api/                 FastAPI + SSE + минималистичный UI
eval/                  questions.yaml (ШАБЛОН!) + run_eval.py
```

## Текущее состояние (обновлять при завершении этапа)

**На 11.09.2026: baseline дописан, 133 теста зелёные, ruff чистый, сервер
поднимается. Ни одного реального ГОСТа ещё не проиндексировано.**

Проверено вручную: `/healthz` отдаёт честное состояние —
`{"status":"empty_index","llm_configured":false,"ocr_available":false}`.

### Что нужно сделать дальше (по порядку)

1. **Ключ провайдера.** `cp .env.example .env`, вписать `LLM_API_KEY` от
   DeepSeek. Без него граф дойдёт до генерации и упадёт с понятной ошибкой.

2. **Tesseract.** На машине разработчика НЕ установлен (`ocr_available:false`).
   Пока его нет, сканы молча пропускаются — в индекс попадут только PDF с
   текстовым слоем. Установка: см. README, для Windows — сборка UB Mannheim
   с языковым пакетом Russian.

3. **Первый реальный корпус.** Положить 3–5 ГОСТов в `data/raw/` (хотя бы один
   скан) и заполнить `data/registry/documents.csv`. Затем
   `uv run python scripts/ingest.py data/raw`. Первый запуск скачает ~2,5 ГБ
   весов BGE-M3 и реранкера — это ожидаемо и происходит один раз.

4. **Проверить поиск до LLM:**
   `uv run python -m gost_rag.retrieval.cli "какой радиус гибки листовой стали 3 мм"`
   Смотреть, доходит ли нужный фрагмент до топа и что меняет реранкер.

5. **Заменить `eval/questions.yaml`.** Сейчас это ШАБЛОН с правдоподобными, но
   **непроверенными** обозначениями ГОСТов. Их нужно заменить на стандарты,
   реально загруженные в корпус, иначе метрики будут нулевыми из-за пустого
   эталона, а не из-за качества поиска (скрипт предупредит об этом).

6. **Зафиксировать baseline-числа** из `eval/run_eval.py` в README. Только после
   этого имеет смысл браться за multi-query / HyDE / семантический чанкинг.

### Известные ограничения baseline

- Уточняющие вопросы: поиск идёт по последнему вопросу как есть, история
  передаётся только генератору. Переписывание запроса — задача v1.
- Встроенный Qdrant комфортен примерно до 20 000 точек. Дальше — `QDRANT_URL`
  на сервер, код менять не нужно. Docker на машине разработчика не установлен.
- Чертежи и схемы не разбираются вообще.
